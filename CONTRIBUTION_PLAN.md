## My Contribution Strategy

I started by commenting on each issue before writing any code, so that the owner knew I was working on it and I wouldn't end up duplicating someone else's effort. Before making any changes I read through the existing code and CONTRIBUTING.md to understand how the project was structured and what style conventions they followed. Nothing kills a PR faster than code that looks out of place. I kept each PR focused on one thing only, which made it easier for the owners to review quickly. I also leaned towards documentation tasks where possible since they carry less risk of breaking something and tend to get merged faster.
